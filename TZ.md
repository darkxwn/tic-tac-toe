# Техническое Задание (ТЗ)
# Проект: «Крестики-Нолики с механикой исчезающего хода» (Infinity Tic-Tac-Toe)

---

## 1. Общее описание проекта

Цель проекта — разработка кроссплатформенной пошаговой игры «Крестики-нолики» с модифицированной механикой ограничения количества активных фигур («исчезающий ход»), исключающей возможность ничьей и трансформирующей игру в тактическую дуэль с контролем времени жизни фигур.

Приложение включает в себя:
* Локальную одиночную игру против алгоритмического бота (3 уровня сложности).
* Локальный мультиплеер для двух игроков на одном устройстве (Hotseat).
* Сетевой онлайн-мультиплеер на расстоянии через легковесный сервер-ретранслятор с комнатами по 4-значным кодам и поддержкой реваншей в той же комнате.
* Кроссплатформенную адаптацию под Web, Mobile (Android/iOS) и Desktop (Windows/macOS/Linux).

## 2. Игровая механика

### 2.1. Игровое поле и базовые правила
* Размер сетки: **3x3** (9 клеток).
* Символы: **Крестик (X)** и **Нолик (O)**.
* Первый ход всегда принадлежит игроку **X**.
* Игроки ходят строго по очереди.

### 2.2. Механика исчезающего хода (FIFO Queue)
* У каждого игрока есть лимит: **не более 3 активных фигур** на доске одновременно.
* Состояние ходов каждого игрока организуется в структуру данных **Очередь (FIFO — First-In, First-Out)** максимальной длины 3.
* **Ходы 1–3 игрока:** фигуры выставляются на свободные клетки и занимают их.
* **Ход 4 и последующие:**
  1. Игрок выбирает любую свободную клетку.
  2. Самая старая фигура этого игрока (поставленная 3 хода назад) удаляется с доски.
  3. Новая фигура добавляется в очередь игрока и на доску.
  4. Клетка, освободившаяся от старой фигуры, становится доступной для любого игрока.

### 2.3. Визуальная градация давности ходов
Каждая фигура на доске имеет визуальный индикатор времени жизни:
1. **Свежая (ход N):** `opacity: 1.0` (яркий, насыщенный цвет).
2. **Средняя (ход N-1):** `opacity: 0.65` (приглушённый цвет).
3. **Критическая (ход N-2, исчезнет следующим ходом):**
   * `opacity: 0.35`.
   * Активный предупреждающий эффект: циклическая пульсация размера (`scale: 0.95 ↔ 1.05`), мерцающий неоновый контур/glow.
4. **Анимация перехода (в момент 4-го хода):**
   * Исчезающая фигура растворяется (`opacity: 0`, `scale: 0`, длительность ~200 мс).
   * Новая фигура появляется с акцентной анимацией отскока (`scale: 1.2 -> 1.0`, длительность ~150 мс).

### 2.4. Условие победы
* Победа фиксируется сразу после совершения хода, если 3 оставшиеся активные фигуры игрока образуют линию (по горизонтали, вертикали или диагонали).
* Линия подсвечивается анимированным росчерком/эффектом. Запускается конфетти-салют.

## 3. Режимы игры

### 3.1. Одиночная игра против бота (Оффлайн)
Бот исполняется полностью на клиенте без обращения к серверу. 3 уровня сложности:

1. **Лёгкий («Новичок»):**
   * 80% ходов совершаются случайно по свободным клеткам.
   * 20% — проверка наличия немедленного выигрыша в 1 ход.
   * Не учитывает исчезновение фигур.

2. **Средний («Тактик» — эвристический алгоритм):**
   * Приоритет 1: если есть ход, приносящий немедленную победу (с учётом удаления старой фигуры) — делает его.
   * Приоритет 2: если соперник следующим ходом побеждает — блокирует ключевую клетку.
   * Приоритет 3: контроль своей очереди (не ставить ход, если исчезнет фигура, удерживающая важную блокировку).
   * Приоритет 4: захват центра, затем углов.

3. **Сложный («Гроссмейстер» — Depth-Limited Minimax):**
   * Алгоритм Minimax с альфа-бета отсечением на глубину **4–6 полуходов**.
   * Оценочная функция позиции:
     * Количество открытых линий (2 в ряд + 1 пусто).
     * «Срок жизни» фигур в линии (линия из новых фигур ценится выше линии с угасающей фигурой).
     * Контроль центральной клетки поля.
   * Практически исключает ошибки со стороны ИИ.

### 3.2. Локальный мультиплеер (Hotseat)
* Игра двух людей на одном экране (ПК, планшет или телефон).
* 100% оффлайн.
* Поочередный ввод с одного устройства.
* Ведение счёта текущей сессии (X побед / O побед).

### 3.3. Онлайн-мультиплеер (По кодам комнат)
* **Система никнеймов:**
  * Игрок указывает свой никнейм (сохраняется в `localStorage`, по умолчанию генерируется, например, «Игрок_42»).
  * Никнейм отображается в лобби, на панели счёта и в индикаторе текущего хода: *«Ход: Алексей (❌)»*.
  * В конце игры пишется имя победителя: *«Победил Алексей!»*.
* **Создание комнаты:** Хост нажимает «Создать комнату» (передавая свой никнейм) и получает уникальный 4-значный код (например, `KZ7A`, только легкоразличимые символы, без `0/O`, `1/I`).
* **Вход в комнату:** Второй игрок вводит 4-значный код и свой никнейм (или переходит по ссылке вида `https://game.app/?room=KZ7A`).
* **Синхронизация:** Обмен ходами происходит через WebSocket сервер-ретранслятор в реальном времени.
* **Механика реванша в той же комнате:**
  * После победы/поражения отображается кнопка «Реванш».
  * При нажатии одним игроком второй получает уведомление: *«[Имя] предлагает реванш»*.
  * При подтверждении обоими:
    * Комната **не пересоздается**, код остаётся прежним.
    * Доска и очереди очищаются.
    * Очерёдность первого хода и фигуры меняются местами (начинает тот, кто был O в прошлой партии, ники привязываются к новым фигурам).
  * При выходе одного из игроков комната расформировывается с уведомлением оставшегося.

## 4. Архитектура и стек технологий

```
+--------------------------------------------------------------+
|                     React 19 + TypeScript                    |
|             Tailwind CSS + Lucide Icons + Canvas-Confetti    |
+------------------------------+-------------------------------+
                               |
       +-----------------------+-----------------------+
       |                       |                       |
+------v------+         +------v------+         +------v------+
|     Web     |         |   Mobile    |         |   Desktop   |
|   (Vite)    |         | (Capacitor) |         | (Tauri v2)  |
+-------------+         +-------------+         +-------------+
```

### 4.1. Клиентская часть (Frontend Core)
* **Фреймворк:** React 19 + TypeScript (строгая типизация всех игровых состояний и протокола сообщений).
* **Сборщик:** Vite (мгновенный HMR, минимальный размер бандла).
* **Стилизация:** Tailwind CSS (темная неоновая тема, адаптивная сетка под мобильные экраны).
* **Анимации:** CSS Transitions / Keyframes + Framer Motion.
* **Звук и эффекты:** Web Audio API (звук клика, звук исчезновения, фанфары победы) + `canvas-confetti`.

### 4.2. Платформенные оболочки
* **Mobile (Android / iOS):** **Capacitor**
  * Сборка нативного Android APK.
  * Интеграция `@capacitor/haptics` для виброотклика при ходе и исчезновении фигуры.
  * Учёт экранных вырезов Safe Area (`viewport-fit=cover`).
* **Desktop (Windows / macOS / Linux):** **Tauri v2**
  * Сборка легкого системного дистрибутива (~10 МБ).
  * Управление с цифровой клавиатуры (Numpad 1–9).
* **Web:** Деплой на Vercel / GitHub Pages с поддержкой PWA (манифест, оффлайн-кэш иконки).

### 4.3. Серверная часть (Relay Server)
* **Стек:** Node.js + библиотека `ws` (легковесный WebSocket сервер без тяжелых зависимостей).
* **Хранение данных:** In-memory (`Map<string, Room>`). База данных не требуется.
* **Автоочистка:** удаление пустых или неактивных комнат по таймауту (10 минут).
* **Бесплатный хостинг:** Render.com (тариф Free Web Service с постоянным WebSocket-соединением).

## 5. Требования к сетевому протоколу (WebSocket JSON)

### Клиент -> Сервер:
* `CREATE_ROOM` `{ playerName }` — запрос на генерацию комнаты.
* `JOIN_ROOM` `{ roomCode, playerName }` — попытка подключиться к комнате.
* `MAKE_MOVE` `{ cellIndex }` — совершение хода в клетку 0..8.
* `REQUEST_REMATCH` — согласие на реванш.
* `LEAVE_ROOM` — выход из сессии.

### Сервер -> Клиент:
* `ROOM_CREATED` `{ roomCode, role: "X", playerName }`
* `JOIN_SUCCESS` `{ roomCode, role: "O", playerName }`
* `GAME_START` `{ currentTurn: "X", players: { X: string, O: string } }`
* `STATE_UPDATE` `{ board, queueX, queueO, currentTurn, lastMove }`
* `GAME_OVER` `{ winner: "X" | "O", winnerName: string, winningLine: number[] }`
* `REMATCH_OFFERED` `{ fromPlayer: string }` — уведомление о предложении реванша от соперника.
* `OPPONENT_DISCONNECTED` — уведомление об обрыве связи с оппонентом.
* `ERROR` `{ message }` — неверный код, комната переполнена и т.д.
